# Panoptes 终版后端分阶段路线图

> 状态：路线图草案  
> 日期：2026-04-30  
> 范围：后端先行的终版实施路线  
> 前置目标文档：`docs/2026-04-30-backend-final-target.md`

## 1. 总路线

终版后端按以下顺序推进：

```text
M0 终版基线冻结
M1 规则底座长期化
M2 道路、连通与城市网络
M3 本地仓储与容量物流
M4 优先级物流与工业链
M5 科技、制度与国家修正深化
M6 网络化战争
M7 大臣默认执行层
M8 信息不对称与失真汇报
M9 PVE 国家
```

核心原则：

- 先国家机器，后大臣困境。
- 先征服胜利，后战略崩溃。
- 先政策优先级，后大臣细化优先级。
- 先半显式物流，不做默认逐批货物模拟。
- 每个阶段都必须能通过 headless scenario 验收。

## 2. M0：终版基线冻结

目标：把终版目标、非目标、术语、系统边界和验收矩阵冻结下来。

交付：

- 终版后端目标文档
- GDD 对照矩阵
- 后端模块责任矩阵
- 非目标清单
- 后端验收矩阵
- M1 任务拆分

验收：

- 每个终版系统都能映射到后端责任
- 明确哪些近期不实现
- 明确哪些只预留接口
- 用户确认后再进入 M1

不做：

- 不写玩法代码
- 不修改 proto
- 不展开大臣 AI

## 3. M1：规则底座长期化

目标：让现有 MVP 后端成为终版国家机器的稳定内核。

重点：

- 固化 `planning / resolving` 阶段边界
- 固化 `PlanningStartRunner` 的次回合生效入口
- 整理事件审计规则
- 把旧壳和未接线系统 feature-gate 或显式拒绝
- 整理 headless harness 为标准验收入口
- 增加跨阶段回归场景

验收：

- `cd server && go test ./...`
- headless 场景覆盖扩张、生产、战斗、占城、科技、政策
- resolving stage 可单独解释和测试

## 4. M2：道路、连通与城市网络

状态：已完成，见 `docs/2026-05-01-backend-m2-regression-gate.md`。

目标：让道路和城市网络成为真实规则对象。

重点：

- 接入 `build_road / repair_road`
- 引入工程单位或等价工程行为
- 城市辖区从固定模型升级为可计算模型
- 建筑、资源点、新城接入 network connected 判定
- 道路破坏和修复进入事件流
- 投影 road status、network status、connected city

验收：

- 断路会让外部设施失效或降效
- 修复道路后下一回合恢复
- 资源设施、新城、建筑能解释自己是否连接国家网络

## 5. M3：本地仓储与容量物流

状态：已完成，见 `docs/2026-05-01-backend-m3-regression-gate.md`。

目标：从全局虚空库存转向城市和国家网络库存。

重点：

- 新增城市仓储状态
- 主城和普通城市拥有本地库存
- 资源产出进入服务城市或本地仓储
- 配方输入从可达库存扣除
- 道路拥有基础运量
- 物流结算先使用连通分量和容量分配
- `Player.Resources` 转为汇总视图或兼容投影

验收：

- A 城有资源但 B 城断连时，B 城不能消费
- 运量不足时配方低效推进
- 资源流动有事件记录

## 6. M4：优先级物流与工业链

状态：已完成，见 `docs/2026-05-01-backend-m4-regression-gate.md`。

目标：把物流从“连通可用”升级为“政策驱动的资源分配”。

重点：

- 增加 logistics demand 模型
- 增加 demand priority tier
- 国策/政策提供 priority profile
- 引入 priority-aware flow allocation
- 多层资源链：原料、中间品、军工/工程材料
- 配方链和下游短缺传播
- 为 min-cost flow 做算法封装

推荐算法：

```text
for each player:
  build logistics graph
  collect supplies and demands
  apply policy priority profile
  for each resource:
    allocate high priority demands first
    consume edge capacities
    emit delivered / shortage / overflow events
```

验收：

- 备战政策会优先保障军需
- 扩张政策会优先保障道路、新城、开拓相关需求
- 同样资源短缺下，不同国策产生不同后果
- 工业链短缺能向下游传播

## 7. M5：科技、制度与国家修正深化

状态：已完成，见 `docs/2026-05-01-backend-m5-regression-gate.md`。

目标：让科技决定国家知道什么，制度决定国家正在实行什么。

重点：

- 扩展科技树依赖和分支
- 科技显式效果覆盖建筑、配方、兵种、制度候选
- 制度槽位玩法完整化
- 制度影响物流优先级、运量、城市、军队和工业链
- 修正系统支持更多作用域
- 增加制度切换成本的预留，不急于启用

验收：

- 科技解锁制度候选
- 制度装填后次回合生效
- 制度能改变物流或工业链后果
- 所有修正来源可审计

## 8. M6：网络化战争

状态：已完成，见 `docs/2026-05-01-backend-m6-regression-gate.md`。

目标：让战争从“摧毁单位和主城”扩展为破坏国家机器。

重点：

- 五个核心谱系：开拓者、步兵、弓手、攻城、破坏/袭扰
- 攻城单位对核心、防御、城墙有特殊规则
- 破坏单位可破坏道路、设施、仓储、补给节点
- 前线补给影响单位战斗能力和恢复
- 防御建筑先强化被动控制，再预留主动防区
- 征服胜利仍为唯一当前胜利

验收：

- 切断道路影响前线补给
- 破坏设施影响经济和生产
- 占城、摧毁主城、破坏国家网络都能进入事件审计

## 9. M7：大臣默认执行层

状态：已完成，见 `docs/2026-05-01-backend-m7-regression-gate.md`。

目标：让大臣成为国家机器的默认执行者。

前置条件：

- M2-M6 基本完成
- 国家机器已有足够真实系统供大臣操作

重点：

- 大臣生成 planning intents
- 国内、经济、军事等部门分工
- 大臣提出建设、物流、科技、制度、军事方案
- 玩家批准、否决、锁定、覆写
- rule-based provider 先行，LLM 只做表达或建议增强
- 大臣命令和玩家命令共用 planning intent 结构

验收：

- 玩家不手动下令时，大臣能完成一回合可执行计划
- 玩家覆写只替换对应意图
- 大臣方案可审计、可回放

## 10. M8：信息不对称与失真汇报

目标：把 `truth`、`observed`、`reported` 正式分层。

重点：

- 可见性层
- 情报来源层
- 大臣汇报层
- 信息失真：遗漏、延迟、误判、偏向性解释
- 亲政令牌：直接查看、强制确认、紧急覆写
- 模式配置：清晰对战、标准 Panoptes、高失真
- 透明度随游戏阶段、制度、大臣和难度变化

验收：

- 非 debug 模式下玩家不默认获得完整 truth
- 同一 truth 可生成不同 observed/reported
- 亲政令牌能临时穿透或校正信息层

## 11. M9：PVE 国家

目标：让服务器控制国家复用玩家规则。

重点：

- AI player 使用同一套 planning intent
- AI 使用城市、物流、科技、制度、战争规则
- 脚本只影响偏好和目标，不绕过规则
- 支持 scenario authoring
- 支持未来 PVE 信息层和大臣层

验收：

- AI 国家能无客户端扩张、生产、补给、打仗
- PVE 行动可审计为 planning intents
- PVE 不需要特殊规则才能跑通基础局

## 12. 阶段依赖

```text
M0 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6 -> M7 -> M8 -> M9
```

允许局部预留接口，但不建议提前实现大臣和信息失真主逻辑。

## 13. 风险清单

### 物流过度仿真

风险：逐批货物、拥堵、延迟和在途状态压过核心体验。  
应对：默认采用半显式 flow 模型，不做持久 shipment。

### 大臣过早接入

风险：国家机器不完整时，大臣只能生成空泛命令。  
应对：M7 前只保留接口和数据形状。

### 胜利条件过早膨胀

风险：经济胜利、战略崩溃、制度崩溃过早加入会拖垮主线。  
应对：近期只保留征服胜利，长期预留 collapse metrics。

### 信息不对称不可读

风险：玩家无法理解失败原因。  
应对：采用阶段性透明度和模式配置，保留清晰对战模式。
