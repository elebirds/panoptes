> 目的：替代“内政阶段 + 军事阶段”的玩家侧硬切分，建立统一规划、统一结算的新回合结构

## 1. 背景与问题

当前版本把一个回合拆成：

1. 内政阶段
2. 内政结算
3. 军事阶段
4. 军事结算

该结构在早期实现上简单，但已经出现明显问题：

- 开拓者、建筑者等单位是地图行动单位，不适合按“是否军事单位”决定能否行动。
- civilian 的移动与坐城、修路、修复被迫跨越“内政 / 军事”边界，语义不顺。
- 玩家本回合下达了开拓、修路等动作，却可能要等到下一回合内政阶段才完整得到反馈，体验迟滞。
- 某些动作已经开始绕过原本的分层边界，在实现上产生“内政逻辑借战斗消息表现”的裂缝。

结论：

- 不再把“内政 / 军事”作为玩家视角的主阶段。
- 改为“统一规划阶段 + 服务端内部统一结算”。

## 2. 设计目标

V2 的目标如下：

- 玩家在一个统一窗口内下达本回合全部意图。
- 所有单位都能在同一回合结构内行动，区别只在于动作类型和能力约束。
- 战斗、移动、坐城、修路、生产、补给、科技都归入同一个权威结算链。
- 明确区分：
  - 什么时候下命令
  - 什么时候看到结果
  - 什么时候开始产生持续收益或规则加成
- 保留 Panoptes 的信息不对称和 AI 部长体验，不要求玩家做传统 4X 式满地图逐单位操作。

## 3. 核心原则

### 3.1 玩家提交的是意图，不是即时改世界

规划阶段内，玩家、部长、脚本都只能提交命令和干预。

除明确允许的纯 UI 信息操作外，本回合真实世界状态不在规划阶段内直接修改，所有权威变更在结算阶段统一发生。

### 3.2 以“动作类型”分类，不以“单位职业”分类

不再问“这个单位是内政单位还是军事单位”，而改问“这个动作属于哪一层”。

动作层建议分为三类：

- 单位动作：移动、攻击、待命、冲锋、撤退
- 地图动作：坐城、修路、修复、建造改良、拆除设施
- 经济动作：生产队列、资源流、补给、科研、政策切换

### 3.3 立即显示，不等于立即产出

很多动作可以在本回合结算中立刻显示其结果，但不一定要在同回合立刻产生完整经济收益。

推荐统一规则：

- 地图存在状态：本回合结算后立刻可见
- 经济产出与长期加成：默认从下回合开始生效

这样可以兼顾：

- 玩家反馈及时
- 规则简单
- 避免同回合连锁爆炸

### 3.4 一个回合只有一个玩家侧主阶段

玩家视角只保留：

1. 规划阶段
2. 结算展示
3. 下一回合

服务端内部仍可保留多个子结算步骤，但这些子步骤不再作为玩家必须手动切换的硬阶段。

## 4. 玩家可见流程

### 4.1 规划阶段

双方同时进行，互相看不到对方操作。

玩家在该阶段可以完成：

- 查看部长汇报
- 调整国策
- 指定科技研究目标
- 调整建筑配方 / 生产队列
- 下达战区意图
- 对具体单位下达命令
- 对部长自动命令进行否决或改写
- 使用亲政令牌进行额外干预

规划阶段结束条件：

- 双方都提交
- 或计时结束自动提交

### 4.2 结算展示

规划结束后，服务端进行统一结算，并向客户端推送一份完整回合结果。

客户端展示顺序建议为：

1. 单位移动
2. 冲突与战斗
3. civilian 地图动作
4. 地图刷新结果
5. 经济与科研结算摘要
6. 回合总结与部长新汇报入口

## 5. 服务端内部结算顺序

以下顺序是 V2 的推荐基线。

### 5.1 Step A：锁定输入

收集并冻结本回合全部输入：

- 玩家命令
- 部长自动命令
- 亲政令牌干预
- 战区指令
- 政策与科技目标切换
- 生产队列与建筑配方切换

之后不再接受新的本回合命令。

### 5.2 Step B：战略状态切换

先处理不依赖地图冲突的“高层决策”：

- 政策切换确认
- 科技研究目标切换确认
- 生产队列 / 配方切换确认
- 部长本回合行为倾向锁定

这些变更在本回合后续结算中可作为“规则上下文”参与判定。

推荐规则：

- 政策切换本回合立即生效，用于影响部长选择、建造倾向、战区执行倾向等。
- 科技只切换研究目标，不在这里直接解锁。
- 生产队列 / 配方切换本回合立即生效，意味着本回合末的生产会按新队列推进。

### 5.3 Step C：单位动作结算

所有单位在同一层结算单位动作，不区分 civilian / military。

包括：

- move
- hold
- attack
- charge
- retreat
- 其他未来战术动作

规则：

- 所有单位基于同一回合起始快照进行同步结算
- civilian 也可以移动
- civilian 是否能执行后续地图动作，取决于其是否在本步骤后仍存活并满足位置条件

### 5.4 Step D：战斗与冲突结算

在单位动作基础上处理：

- 节点冲突
- 近战
- 远程攻击
- 攻城
- 破坏
- civilian 被接敌后的移除或失败

该步骤结束后，得到本回合单位层的最终幸存状态与最终站位。

### 5.5 Step E：地图动作结算

该步骤处理本回合成功执行的地图动作。

仅允许满足条件的单位执行：

- 到达目标点
- 本回合结算后仍存活
- 未被控制、驱离、击退或其他规则阻止

典型动作：

- `settle_city`
- `build_road`
- `repair_road`
- `build_improvement`
- `repair_improvement`
- `remove_improvement`

### 5.6 Step F：地图刷新

在地图动作完成后统一刷新：

- 领土归属
- 道路连通性
- 视野
- 建筑 / 设施状态
- 补给网络拓扑
- 占领和控制状态

此时玩家可以在本回合结算展示中立刻看到新城、新路、新领土和地块变化。

### 5.7 Step G：经济与科研结算

在最终地图状态基础上处理：

- 资源流动
- 生产推进
- 单位补给与维护
- 科研点增长
- 研究完成判定
- 回合末恢复 / 衰减 / 冷却

该步骤统一使用“本回合末的地图状态 + 激活状态”进行结算。

### 5.8 Step H：胜负检测与回合推进

处理：

- 胜负条件判定
- 回合数推进
- 下回合部长汇报生成
- 下一回合开始消息

## 6. 各系统详细规则

### 6.1 单位移动

规则建议：

- 所有单位共享统一移动框架
- 不同单位只在移动力、能力标签、可用动作上不同
- 多回合持续行军继续保留
- civilian 的移动不再挂靠“军事阶段”

效果时机：

- 命令：规划阶段提交
- 位移结果：本回合结算展示
- 新位置参与后续战斗 / 地图动作 / 补给结算

### 6.2 战斗

规则建议：

- 战斗与移动属于同一单位层结算链
- 不是单独的玩家阶段
- 战斗结果在本回合结算中立刻展示

效果时机：

- 命令：规划阶段提交
- 伤害 / 死亡 / 攻城结果：本回合结算展示
- 造成的地形控制变化：地图刷新后立刻可见

### 6.3 坐城

推荐采用“命令先提交，坐城在结算时执行”。

原因：

- 可以和移动、拦截、战斗形成统一规则
- 可以避免规划阶段即时改图导致的权威混乱
- 可以让“是否成功坐城”成为本回合行动结果的一部分

成功条件建议：

- 开拓者本回合结算后仍存活
- 开拓者最终位于目标格
- 目标格满足建城约束
- 未被敌对占据或其他规则阻止

成功后的效果拆分：

- 立即显示：
  - 新城出现在地图上
  - 开拓者被消耗
  - 领土刷新
  - 视野刷新
- 下回合生效：
  - 新城产出
  - 新城招募
  - 新城正式作为生产节点参与经济
  - 新城提供常规回合收益

额外建议：

- 新城可以在本回合结算后立即成为地图上的“控制源”和“视野源”
- 但不建议同回合立刻给完整经济产出，避免扩张回合收益过爆

### 6.4 建筑者动作

建筑者与开拓者一样，建议采用“规划阶段下命令，结算阶段执行”。

推荐规则：

- 建筑者可以先移动，再在回合末执行一个地图动作
- 若本回合被杀、被阻断、未到位，则动作失败

常见动作：

- 修路
- 修复道路
- 建改良
- 修复改良
- 拆除改良

效果建议分两层：

- 立即显示：
  - 路、设施、改良的地图状态变化
- 收益生效：
  - 默认下回合开始提供经济收益

其中道路可做一个特殊规则：

- 新建 / 修复道路在本回合地图刷新后立即改变连通性
- 因而可以影响本回合末的补给网络

这样工程动作会保留战略价值，但不会让新改良本回合立刻多跳一轮产出。

### 6.5 生产

推荐规则：

- 规划阶段切换生产队列 / 配方
- 回合末统一推进生产
- 新完成的单位 / 建筑进入世界，但默认从下回合开始可执行主动动作

原因：

- 避免“本回合刚生产出来就立刻参与同回合移动或战斗”
- 简化结算顺序

如果需要展示：

- 本回合结算中可以显示“某城完成了某单位 / 某建筑”
- 但其主动行动能力从下回合开放

### 6.6 补给

推荐放在回合末结算。

原因：

- 补给线是否连通，本来就取决于本回合战斗、道路破坏、道路修复和领土变化
- 放在回合末最符合玩家直觉

推荐口径：

- 补给网络按本回合地图刷新后的最终拓扑判定
- 但补给源是否有效，要看其是否处于“已激活”状态

因此：

- 老城、老设施、已激活据点可在本回合末作为补给源
- 本回合新坐下的城默认不作为完整补给源

这能避免“本回合极限坐城直接解掉前线断粮”的不稳定玩法。

### 6.7 领土刷新

推荐放在地图动作之后、经济结算之前。

这样可以保证：

- 新城 / 新据点能立即改写地块归属
- 被摧毁或被移除的控制点会立即失去影响
- 最终经济、补给、视野都基于同一份刷新后的地图

### 6.8 政策

推荐规则：

- 规划阶段可切换政策
- 结算一开始确认切换
- 本回合立即影响：
  - 部长倾向
  - 自动命令权重
  - 某些回合内修正值

需要谨慎的一点：

- 若政策附带大幅数值加成，建议只影响本回合结算中“应当受战略决策影响”的部分
- 不要让政策变成临门一脚式的纯数值开关

可接受的立即生效范围：

- 部长行为权重
- 生产 / 研发 / 扩张优先级
- 某些非瞬时的全局修正

不建议的做法：

- 规划阶段末切政策，立刻对所有已宣告的战斗做巨额瞬时倍率改写

### 6.9 科技树

推荐拆成三层：

1. 研究目标选择
2. 科研点积累
3. 科技解锁生效

推荐规则：

- 规划阶段：只切换研究目标
- 回合末：结算科研点并判定是否完成
- 下回合开始：科技正式生效

该规则的优点：

- 简单
- 稳定
- 避免“本回合刚研究完，立刻影响同回合生产 / 战斗 / 建造合法性”

科技完成时，本回合结算中可以立刻展示“已完成研究”的反馈，但正式效果在下一回合启用。

## 7. 即时显示与生效时机总表

| 系统 | 命令提交 | 结果展示 | 持续收益 / 持续规则生效 |
|---|---|---|---|
| 移动 | 规划阶段 | 本回合结算 | 立即体现在最终站位 |
| 战斗 | 规划阶段 | 本回合结算 | 立即体现在单位存亡与地图控制 |
| 坐城 | 规划阶段 | 本回合结算 | 新城收益下回合生效 |
| 修路 / 修路修复 | 规划阶段 | 本回合结算 | 连通性本回合末生效 |
| 建改良 / 修复改良 | 规划阶段 | 本回合结算 | 产出下回合生效 |
| 生产队列切换 | 规划阶段 | 本回合结算摘要 | 本回合末按新队列推进 |
| 单位 / 建筑完成 | 规划阶段此前已存在队列 | 本回合结算 | 新完成对象下回合可主动行动 / 完整运转 |
| 补给 | 无单独命令 | 本回合结算 | 本回合末即时判定 |
| 领土刷新 | 无单独命令 | 本回合结算 | 本回合末即时生效 |
| 政策切换 | 规划阶段 | 本回合结算摘要 | 本回合结算开始即生效 |
| 科技目标切换 | 规划阶段 | 本回合结算摘要 | 仅影响研究指向，本回合有效 |
| 科技完成 | 无额外命令 | 本回合结算展示 | 下一回合正式生效 |

## 8. 对 AI 部长系统的意义

V2 不削弱部长系统，反而更适合部长驱动体验。

原因：

- 玩家不需要在“内政界面”和“军事界面”来回切脑回路
- 部长可以在同一个规划阶段内提交跨系统建议
- 军事部长可以给出战区意图和单位建议
- 农业 / 工程部长可以对道路、扩张、生产线给出建议
- 玩家只需在一个统一窗口里做有限干预

部长系统在 V2 下的推荐职责：

- 部长负责生成默认意图与解释
- 玩家负责修改少量关键意图
- 服务端负责统一结算，不让部长直接越过规则改世界

## 9. 推荐的协议与状态机方向

本节不是实施细案，只定义方向。

### 9.1 玩家侧阶段

建议最终收敛为：

- `planning`
- `resolving`

若需要显示上一回合信息，可额外有短暂的：

- `turn_report`

但不再保留“domestic_planning / combat_planning”作为玩家必须切换的主流程。

### 9.2 结算消息

推荐长期方向：

- 用统一的 `TurnSettlement` 或等价消息承载完整回合结果
- 其中可包含多个事件段：
  - `unit_events`
  - `map_events`
  - `economy_events`
  - `research_events`

这样客户端播放和缓存更新会更稳定。

### 9.3 命令模型

推荐长期方向：

- 保留按领域分文件的 proto 组织方式
- 但在服务端内部统一收敛成“本回合命令集”

例如：

- `UnitOrder`
- `MapActionOrder`
- `EconomicOrder`
- `StrategicOrder`

最终由同一个结算器读取。

## 10. V2 的基线裁决

若后续实现中出现歧义，优先按以下裁决：

1. 玩家只在统一规划阶段下命令
2. 所有真实状态变更统一在结算中发生
3. 地图变化可以本回合立刻显示
4. 新增的经济收益默认下回合生效
5. 补给按本回合末最终地图判定
6. 新科技默认下回合生效
7. 不因单位是 civilian 就把其行动塞进单独阶段

## 11. 一句话总结

V2 的核心不是把“内政”和“军事”重新换个名字，而是把回合结构从“按题材切阶段”改成“按结算层切步骤”：

- 玩家只有一个规划阶段
- 服务端内部按单位层、地图层、经济层统一结算
- 结果本回合立刻反馈
- 长期收益按规则延后到下回合生效

这套结构更适合 Panoptes 的部长制、信息不对称和早期快速迭代，也能自然容纳开拓者、建筑者、军队和未来更多地图行动单位。

## 12. 推荐的后续落地顺序

若决定按本草案推进，建议实施顺序如下：

1. 先改规则文档与术语，明确玩家侧不再区分“内政阶段 / 军事阶段”。
2. 再改服务端状态机，从双 planning phase 收敛到统一 planning phase。
3. 然后把 civilian 的移动与地图动作从旧阶段边界中解耦出来。
4. 最后再统一 settlement 消息和客户端播放模型。

推荐不要一开始就追求“一次性重写完所有系统”，而是先把：

- 命令收集模型
- 统一结算顺序
- 生效时机口径

这三件事固定下来。
