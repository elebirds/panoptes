# Panoptes 游戏设计文档（新版 GDD）

> 状态：新版设计基线草案  
> 日期：2026-04-15  
> 适用范围：游戏总体设计、系统边界、阶段演进路线  
> 说明：
> - 本文不以当前实现现状为约束，而以目标设计为准。
> - 回合结构以 `docs/TURN_V2_REFACTOR_PLAN.md` 的统一 `planning / resolving` 为基线。
> - 旧版 `docs/gdd/GDD_v0.1.md`、`docs/gdd/POLICY.md` 中与本文冲突之处，以本文为准。

## 1. 项目定位

Panoptes 是一款回合制联机国家经营对抗游戏。玩家扮演君主，在不完全信息和有限干预能力下，决定国家发展、城市扩张、生产体系与军事行动，并在统一结算中承受不可逆后果。

Panoptes 的长期核心体验不是“全知全能地微操国家”，而是“在国家机器并不完全透明的情况下做决策”。但当前版本不强行实现全部 Panoptes 特色，而是优先建立稳定、可扩展的 4X / 战棋底座，再逐步接入大臣系统、内政迷雾、物流网络与更复杂的国家机器。

一句话定位仍然是：

> P 社让你当上帝，我们让你当人。

## 2. 设计原则

本文的系统设计遵循以下原则：

1. 玩家侧只有一个主操作阶段：`planning`。
2. 所有真实状态变更统一在 `resolving` 中发生。
3. 地图变化优先即时反馈，持续收益通常延后到下一回合。
4. 科技、政策、建筑、配方、单位共享统一的资源、点数与修正规则。
5. 当前先用直接指挥建立玩法闭环，后续升级为“大臣默认执行 + 玩家有限覆写”。
6. 当前物流、迷雾和 PVE 可暂缓，但接口和演进路线必须在设计上成立。

## 3. 阶段路线

Panoptes 的新版 GDD 明确分为三层设计口径。

### 3.1 当前基线 / MVP

当前版本优先建立以下闭环：

- 统一 `planning / resolving` 回合
- 合法地块自由建城
- 城市核心、资源建筑、基础生产建筑
- 一级原始资源
- 全局虚空仓储
- 两类全局点数：科研产出、建造/工业产出
- 科技推进与基础政策框架
- 开拓者与步兵两种单位
- 玩家直接指挥
- 基础战斗与主城核心摧毁判负

### 3.2 中期演进

中期优先补齐：

- 五个核心兵种谱系
- 一级到二级资源加工链
- 工程单位
- 制度槽位实装
- 道路“连通才激活”
- 骑兵等高机动单位
- 大臣生成默认命令、玩家覆写关键动作

### 3.3 长期目标

长期目标是完整的 Panoptes 体验：

- 大臣系统接管默认执行层
- 战争迷雾 + 内政迷雾
- 失真汇报与有限亲政
- 主城/城市本地仓储
- 道路物流与运量限制
- 多层工业链
- 主动防御建筑
- PVE 与更复杂的国家机器

## 4. 核心回合结构

### 4.1 玩家可见阶段

玩家可见流程固定为：

- `planning`
- `resolving`
- `next_turn`

不再保留“内政阶段 / 战斗阶段”作为玩家必须切换的双主阶段。

### 4.2 Planning 阶段

在 `planning` 中，玩家统一完成本回合全部决策，包括：

- 选择科技研究目标
- 切换当前国策
- 调整制度槽位配置
- 指定建筑和配方
- 下达单位命令
- 发起建城与建设类指令
- 后续可扩展为大臣授权、否决与覆写

规划阶段提交的是“意图”，不是即时改世界。

### 4.3 Resolving 阶段

服务端在 `resolving` 中按固定顺序结算：

1. 锁定输入与战略状态
2. 单位动作结算
3. 战斗与冲突结算
4. 地图动作结算
5. 地图刷新
6. 经济、配方、补给、科研结算
7. 胜负检测与回合推进

### 4.4 生效时机总规则

- 本回合立即显示：移动、战斗结果、建城落地、道路完成、建筑受损、领土刷新
- 本回合末参与判定：道路连通性、补给网络、最终控制状态
- 下一回合正式生效：新城常规产出、新建筑完整运作、新单位主动行动、新科技正式效果、新制度正式效果

这条规则是全文基线：地图先反馈，收益后生效。

## 5. 地图、城市与扩张

### 5.1 地图

当前推荐以固定对称地图作为基线，后续可扩展程序化生成。地图采用格点与统一结算模型。

地图可以同时存在：

- 玩家初始主城
- 少量预置遗址、关键据点或高价值争夺点
- 可由玩家自由建城的合法地块

### 5.2 城市模型

城市不是纯抽象节点，而是以“城市核心建筑”为中心的国家管理单元。

每座城市至少包含：

- 一个城市核心建筑
- 一个固定初始辖区
- 若干隶属该城市的城市内建筑
- 可绑定到该城市的城外设施

主城只是开局已存在、规格更高的特殊城市核心。

### 5.3 建城规则

开拓者可在任意合法地块建城。推荐默认约束：

- 不可建在不可建造地形上
- 不可建在既有建筑占位上
- 不可建在敌方核心控制区
- 必须满足最小城距
- 特殊遗址、奇观、关键资源点默认不可直接覆盖，除非未来规则允许

建城成功后：

- 本回合立即显示：城市核心落地、开拓者消耗、领土刷新、视野刷新
- 下一回合正式生效：常规产出、建筑槽位、生产资格、制度增益

### 5.4 城市辖区

当前版本先采用固定初始辖区，不引入主动扩张玩法，但明确该概念存在。

中后期可引入：

- 城市等级
- 扩张值 / 文化扩张 / 行政扩张
- 科技与制度影响辖区范围

## 6. 建筑系统

### 6.1 统一建筑底座

所有建筑共享统一底座：

- 建筑 ID
- 玩家所有权
- 城市隶属或设施归属
- 合法放置规则
- 生命 / 耐久
- 激活状态
- 可用配方列表
- 显式效果
- 修正效果
- 特殊能力标签

### 6.2 建筑分类

推荐建筑标签包括：

- `core`：城市核心
- `extraction`：资源采集设施
- `processing`：加工建筑
- `production`：生产建筑
- `storage`：仓储建筑
- `defense`：防御建筑
- `governance`：行政、制度、科研类建筑

### 6.3 双重归属：所有权与隶属关系

建筑不只是“归某玩家”，而是具有双重归属：

- `玩家所有权`
- `城市隶属关系`

这使“城市内建筑必须在城市范围内”和“城外资源设施仍然为某座城市服务”可以同时成立。

### 6.4 城市内建筑与城外设施

建筑分为两类：

`城市内建筑`

- 必须位于某座城市辖区内
- 包括城市核心、加工建筑、兵营、仓储、行政科研建筑、大部分防御建筑

`城外设施`

- 可位于城市辖区外
- 必须满足特定地块条件
- 默认绑定一个服务城市或归属城市
- 当前主要指资源采集设施

### 6.5 军事建筑路线

当前：

- 仅保留被动防御建筑
- 主要承担耐久、防御修正、控制源与守城辅助功能

长期：

- 扩展为可主动攻击的防御建筑

## 7. 建筑状态、占领与摧毁

### 7.1 三种结果

建筑结局不只分“占领 / 摧毁”，而统一为三种：

- `停用`
- `接管`
- `摧毁 / 废墟化`

### 7.2 停用

建筑仍存在，但由于失去控制、失去连通、失去服务城市、输入不足或被压制而不运作。

### 7.3 城外设施接管

城外设施采用“先失效，后接管”的规则：

- 敌方第一次在结算后控制该地块时，设施先进入失效/争夺中状态
- 原拥有者立即失去产出
- 若敌方持续控制达到 `N` 回合后，设施正式接管

其中 `N` 应设计为可调整参数，而不是写死常量。

### 7.4 城市陷落时的建筑命运

城市内建筑在城市陷落时，不采用“全城统一原样接管”，而采用“部分接管，部分废墟”的标签化规则：

- 基础民生、仓储、基础加工类建筑：可被接管
- 高级军工、制度、核心防务类建筑：更倾向于转为废墟或失效

这样可以避免“攻下一座城就完整白赚整套高级国家机器”。

## 8. 资源系统

### 8.1 资源层级路线

资源层级采用以下演进路线：

- 当前：一级原始资源
- 中期：一级 + 二级加工资源
- 目标：多层复杂资源体系

### 8.2 当前基线资源

当前推荐原始实体资源：

- 粮食
- 木材
- 矿石

这些资源可库存、可结转、可作为配方输入输出。

### 8.3 仓储与物流路线

当前采用全局虚空仓储：

- 资源归国家所有后进入全局共享库存
- 不做本地仓储
- 不做道路经济物流

中期演进为：

- 资源点、建筑和新城必须连通国家网络才激活

长期演进为：

- 主城/城市仓储
- 道路运输
- 运量限制
- 资源调配策略

## 9. 点数系统

### 9.1 基本定义

点数是绑定在玩家国家层的非库存型能力值，不以长期囤积形式存在，而按回合结算生效。

点数体现“国家本回合能做多少事”，与实体资源的“国家拥有什么”严格区分。

### 9.2 当前基线

当前只保留两类全局点数：

- `科研产出`
- `建造 / 工业产出`

### 9.3 后续扩展

长期可加入：

- 行政 / 治理产出
- 文化或其他制度支撑资源

但不纳入当前 MVP 基线。

## 10. 修正系统

### 10.1 命名与职责

GDD 中统一使用：

- 修正系统
- 国家修正
- 全局修正

实现层可继续使用 `modifier` 概念。

### 10.2 混合模型

Panoptes 的效果分为两层：

`显式效果`

- 解锁建筑
- 解锁配方
- 解锁兵种谱系
- 解锁制度候选
- 授予单位
- 增加制度槽位

`修正效果`

- 科研产出修正
- 建造 / 工业推进率修正
- 单位属性修正
- 特定建筑、城市或配方效率修正
- 守城、防御或维护修正

该模型统一承接科技、政策、建筑等来源。

## 11. 科技系统

### 11.1 基本结构

科技系统是长期发展树，包含：

- 图标
- 名称
- 描述
- 前置依赖
- 研究成本
- 分支与层级
- 解锁效果
- 修正效果

### 11.2 科技推进

科技推进采用“非库存科研产出 + 研究进度条”模型：

- 玩家在 `planning` 中选择当前研究目标
- 回合末自动把科研产出灌入该科技进度
- 进度存储在科技条目上，而不是存储为自由科技点

### 11.3 科技切换

当前基线：

- 切换研究目标时，已积累进度完全保留

目标方向：

- 未来可研究“部分损耗切线”模型

### 11.4 科技生效时机

- 本回合结算显示完成
- 下一回合正式生效

### 11.5 科技效果范围

科技可提供：

- 解锁建筑
- 解锁配方
- 解锁兵种谱系
- 解锁制度候选
- 授予单位
- 提供国家修正

## 12. 政策系统

科技系统与政策系统独立，但部分制度可由科技解锁。

### 12.1 双层政策系统

政策分为两层：

`国策层`

- 表示本回合国家总方向
- 在 `planning` 中切换
- 本回合结算开始即生效

`制度层`

- 表示长期法令、制度、国体或国家机器配置
- 由科技解锁候选
- 在有限制度槽位中启用
- 默认下一回合开始生效

### 12.2 制度启用规则

制度采用“解锁进入候选池，按槽位启用”的模型：

- 科技决定玩家“能不能使用该制度”
- 玩家决定“当前启用了哪些制度”

### 12.3 制度切换

当前基线：

- 制度调整在 `planning` 中决定
- 默认下一回合开始生效
- 不引入稀缺切换代价

长期：

- 可研究加入稀缺政治成本或行政代价

### 12.4 制度类别与影响范围

制度不再与国策共用同一套配置。国策是短期姿态，制度是长期国家结构；国策回答“这一回合国家优先做什么”，制度回答“这个国家默认如何组织权力、生产、贸易、军队与行政”。

制度按类别组织。同一类别同时最多启用一个制度，以表达不同治理维度内的排他选择，而不是把所有制度都放进一个无差别卡槽池。推荐基础类别包括：

- `power`：权力制度，决定中央、地方与大臣之间的权力分配
- `citizenship`：公民制度，决定国家默认优先保护与动员的人群
- `economy`：经济制度，决定生产组织与短缺分配
- `trade`：贸易制度，决定市场、贸易与外部资源组织
- `military`：军事制度，决定军队维护、动员与补给结构
- `administration`：行政制度，决定信息汇总、报告精度与执行链条

制度影响国家的方式应集中在长期结构，而不是一次性命令：

- 提供国家修正，例如科研产出、配方推进、物流容量或单位维护修正
- 改变物流优先级，例如优先保障工业、军事、研究、贸易或扩张链条
- 提供治理效果，例如报告精度、大臣自主度、行政效率或未来稳定性压力
- 通过科技或其他显式效果进入候选池，必要时也可扩展制度槽位

当前第一版应先保证数据、候选池、类别互斥、启用和效果链路成立。完整政治过程，例如利益集团、立法阻力、改革概率、政治代价和社会反弹，属于长期目标。

### 12.5 与国策的区别

国策与制度都影响国家，但它们不应承担同一种设计职责。

| 对比项 | 国策 | 制度 |
|---|---|---|
| 时间尺度 | 短期，按回合表达当前方向 | 长期，表达国家机器的持续结构 |
| 选择方式 | 通常一回合选择一个当前方针 | 按类别启用，同类别互斥 |
| 生效口径 | `planning` 确认，本回合结算开始生效 | `planning` 调整，下一回合正式生效 |
| 设计重点 | 权重、倾向、临时修正、大臣关注方向 | 国家修正、物流优先级、治理效果、制度候选 |
| 玩家感受 | “我现在要求国家做什么” | “我让国家成为怎样的组织” |

## 13. 配方系统

### 13.1 定义

配方是生产与转换的核心抽象。建筑、城市或特定系统通过配方，把资源、点数和建筑能力转化为具体结果。

### 13.2 配方结构

推荐字段包括：

- 所属建筑或合法载体
- 配方类型
- 输入资源
- 输入点数或推进需求
- `work_cost`
- 每回合推进率
- 产出
- 输入不足惩罚

### 13.3 当前产出范围

当前配方可统一产出：

- 实体资源
- 单位
- 点数增量或推进
- 局部状态

当前不允许配方直接产出长期制度变化。

### 13.4 建筑运行规则

当前：

- 单建筑同一时间只激活一个配方

后期：

- 可研究扩展为配方队列

### 13.5 输入不足惩罚

当前基线采用：

- 低效推进
- 停滞
- 延迟惩罚

不采用简单硬报错，也不默认引入强反噬。

## 14. 单位系统

### 14.1 当前与目标指挥模型

当前基线：

- 玩家直接下达单位命令

长期目标：

- 大臣默认生成与执行命令
- 玩家有限覆写关键动作

### 14.2 平民单位路线

当前：

- 只有开拓者

目标系统：

- 开拓者负责建城
- 工程单位负责道路、修复、野外改良、前线工事
- 城市内部建筑仍由城市 / 配方 / 建造队列完成

### 14.3 兵种路线

当前 MVP：

- 开拓者
- 步兵

中期扩展为五个核心谱系：

- 开拓者
- 步兵 / 战士
- 弓手
- 攻城单位
- 破坏 / 袭扰单位

后期再进一步扩展高机动与特化兵种，例如骑兵。

## 15. 军事与战斗系统

### 15.1 当前基线

当前先建立可用的直接指挥战棋底座：

- 移动
- 接敌
- 冲突
- 占位
- 防御核心摧毁

### 15.2 军事建筑

当前：

- 仅保留被动防御建筑

长期：

- 扩展主动防御建筑

### 15.3 战争目标

当前战争核心仍是摧毁敌方主城核心。

长期战争目标会逐步从“单位战斗”扩展到：

- 基础设施破坏
- 国家网络切断
- 物流瘫痪
- 大臣与制度协同失灵

## 16. 信息系统与大臣系统

### 16.1 当前基线

当前版本默认展示服务端权威信息：

- 不做战争迷雾
- 不做内政迷雾
- 不做大臣失真

### 16.2 设计预留

虽然当前不实现，但必须预留以下分层：

- 可见性层
- 信息来源层
- 汇报层
- 玩家直视信息与官僚汇报信息分离

### 16.3 大臣系统路线

当前：

- 保留接口

中后期高优先级：

- 大臣生成默认命令
- 玩家有限覆写
- 国家部门分工
- 汇报与建议

长期：

- 忠诚度、能力、性格、失真、亲政干预

## 17. PVE 系统

当前不开发服务器控制的 PVE 势力。

长期目标是在 PVP 底座稳定后，复用同一套规则引入服务器控制国家或脚本化势力，而不是另起一套玩法。

## 18. 当前 MVP 基线总表

当前正式基线如下：

- 统一 `planning / resolving`
- 固定地图 + 合法地块自由建城
- 主城核心摧毁判负
- 一级原始资源
- 全局虚空仓储
- 两类全局点数：科研产出、建造 / 工业产出
- 科技自动推进研究进度，切线保留进度
- 双层政策结构写入设计，当前优先保证国策层
- 统一建筑底座
- 城市辖区 + 城外设施双轨制
- 单建筑单激活配方
- 输入不足时低效推进 / 延迟惩罚
- 玩家直接指挥
- 单位仅有开拓者与步兵
- 只有开拓者作为平民单位
- 军事建筑仅有被动防御能力
- 不做迷雾、不做大臣失真、不做 PVE

## 19. 中期演进重点

中期优先补齐：

- 五个核心兵种谱系
- 一级到二级资源加工链
- 工程单位
- 制度槽位实装
- 道路“连通才激活”
- 大臣默认命令生成
- 玩家覆写关键动作
- 骑兵等高机动单位

## 20. 长期目标总结

Panoptes 的完整目标形态是：

- 玩家以君主身份面对不完整信息和有限控制权
- 大臣构成国家机器的执行层和失真信息层
- 科技决定国家知道什么
- 制度决定国家正在实行什么
- 建筑和配方决定国家能把能力转成什么
- 道路和仓储决定国家能把物资送到哪里
- 战争不仅是消灭单位，更是破坏和重构对方国家机器的网络拓扑

这意味着当前 GDD 的任务不是一次性实现终局形态，而是建立一条不会自我冲突的演进路线：

- 当前先把底座跑通
- 中期逐步补齐特色系统
- 长期再兑现 Panoptes 的完整辨识度
