## 2. 核心定位与差异化

### 2.1 一句话定位

> **P社让你当上帝，我们让你当人。**

### 2.2 核心体验

玩家扮演一国君主，但不是全知全能的上帝，而是一个信息残缺的领导者。玩家感知世界的唯一方式是通过AI部长的汇报，而部长有私心、会犯错、会互相矛盾。玩家要在不完整的信息下做不可逆的决策。

赢的人不是操作最精确的，而是判断力最强的——能够识别部长建议里的偏差，能够在多方矛盾的信息里拼出真实的局势，并在关键时刻做出正确的选择。

### 2.3 与现有游戏的本质区别

**与文明系列的区别**

文明是节点游戏：城市独立产出，战争是用军队占领对方城市，建设和战斗是两个相对独立的系统，玩家始终处于上帝视角，信息完全透明。

本游戏是网络游戏：节点只有在网络中才有意义，孤立的节点会自然衰亡，战争的本质是重构对方的控制网络拓扑。玩家看到的世界是AI部长构建的主观图景，不是客观事实。

**与P社游戏的区别**

P社给玩家全局视角，所有信息可查，决策是计算问题。本游戏的信息经过部长的过滤和失真，决策是判断问题。玩家不是在算最优解，而是在评估信息可靠性。

**AI的融合深度**

本游戏中AI不是表现层的包装，而是游戏的感知层和执行层。玩家通过AI部长感知世界，部长的自主行动直接改变游戏状态，政策系统的执行由AI完成。去掉AI，游戏无法运行，而不只是"体验变差"。

### 2.4 商业潜力论据

策略城建是成熟赛道，莉莉丝自身有《万国觉醒》验证了市场规模。本游戏的增量在于：

- AI部长天然是角色养成层，是传统策略游戏从未认真做过的付费维度（历史名将部长、稀有性格部长）
- 把策略游戏从"算法博弈"变成"关系博弈"，拓宽了受众边界
- 大模型推理成本持续下降，现在是第一批能把这件事做好的窗口期

## 3. 世界观与叙事框架

### 3.1 基本世界观

游戏发生在一个架空的中世纪风格世界。玩家是一国君主，统治一片领土，与其他君主争夺地图上的资源和战略要地，最终目标是攻破对方的主城。

世界观不追求严肃的历史考据，而是追求戏剧性的君臣关系和信息博弈的紧张感。

### 3.2 叙事核心：君臣关系

每局游戏的叙事主轴不是"我打赢了"，而是"我和我的大臣们经历了什么"。

部长不是无感情的工具，而是有立场、有记忆、有私心的角色。他们记得自己的建议被采纳还是拒绝，记得哪次判断是对的哪次是错的，记得和其他部长之间的争执。这些记忆会影响他们之后的行为和汇报方式。

每局游戏结束时，部长们会对这段历史做叙事性的总结，形成独属于这局游戏的故事。两局游戏的地图可能相同，但君臣关系的故事一定不同。

### 3.3 关键节点命名

地图生成时，重要的战略节点（高价值资源点、中央争夺点、山地险关）由LLM根据地形特征自动生成名称。例如山地节点可能叫"铁岭"，河流节点可能叫"渡口"，中央争夺点可能叫"龙脊"。

部长的所有汇报都使用这些名称而不是坐标，让玩家对地图形成情感记忆，也让战报更有叙事感。

### 3.4 胜负叙事

游戏结束时不弹出简单的"胜利/失败"界面，而是由部长们对这段历史做总结。

胜利时，部长们会回顾关键决策，评价君主的判断，可能有人夸奖，也可能有人表示早就建议这样做。失败时，部长们会各自表态，有人表示遗憾，有人隐晦地提到某次被拒绝的建议。

这些总结由LLM根据本局实际发生的事件生成，不是预设文本，保证每局独一无二。

## 4. 地图系统

### 4.1 基本参数

地图采用正方形格子，距离计算使用曼哈顿距离（上下左右四个方向，不计斜向）。

Gamejam版本使用写死的固定地图，但代码层面留好地图生成器的接口，方便后续扩展为程序化生成。固定地图需要保证双方出生点的对称性，即双方距离各类资源点的机会相等。

地图推荐尺寸：约20×20格子。实际可建造和可活动的区域在这个范围内，边缘可设置不可通行的障碍地形。

### 4.2 地形类型

地图上的每个格子有一种地形类型，地形影响兵种移动消耗和战斗加成：

**平原**
最基础的地形，无特殊加成。大部分格子为平原。兵种在平原上按正常移动力移动（道路格消耗1点移动力，非道路格消耗2点移动力）。适合建造农场等生产建筑。

**山地**
只有特定兵种（攻城兵、步兵）可以进入。骑兵无法进入山地格子。守方在山地享有防御加成（受到伤害×0.7）。矿山只能建造在山地格子上，是铁矿石的主要来源。

**森林**
所有兵种可以进入，但非道路情况下移动消耗额外+1（即消耗3点移动力）。守方在森林享有隐蔽加成（敌方远程攻击命中率-20%）。伐木场只能建造在森林格子附近（相邻格），是木材的主要来源。

**河流**
河流格子本身不可建造建筑，兵种无法直接通过河流格子，必须通过桥梁（道路经过河流时自动视为桥梁）。河流对防线的分割作用非常重要，拥有河流一侧的防守方享有天然优势。

### 4.3 资源点分布

地图上预设若干资源点，分为三类：矿石点（山地附近）、木材点（森林附近）、粮食点（平原上的肥沃土地）。

资源点的分布原则：
- 双方近端各有数量相等的基础资源点，保证开局公平
- 地图中央放置1～2个高价值资源点（产出量是普通资源点的1.5倍），这些点双方距离相等，天然成为全局争夺焦点
- 资源点的具体位置在固定地图中手动设计，保证战略深度

资源点没有建筑的情况下不产出任何资源。玩家必须先占领资源点（派兵驻守1回合），再在上面建造对应的采取设施，才能开始产出资源。

## 5. 城镇与疆界系统

### 5.1 城镇类型

游戏中存在两种城镇：

**主城**
每个玩家有且只有一个主城，游戏开始时已建好，位于地图己方一侧。主城是胜负判定的核心，主城血量归零即判负。主城周围4格（曼哈顿距离）为核心安全区。

**卫星城**
地图上预设若干空城堡，初始状态为中立，不属于任何玩家。玩家可以通过派兵占领空城堡（驻守1回合后完成占领），将其发展为己方的卫星城。卫星城可以建造建筑，可以生产兵种，是扩张资源版图的重要方式。

### 5.2 核心安全区

每个城镇（主城和卫星城）以自身为中心，曼哈顿距离4格以内的区域为该城镇的核心安全区。核心安全区有以下特性：

- 只有城镇所有者可以在其中建造建筑
- 敌方兵力进入核心安全区会触发战斗，但即使敌方获胜也无法在安全区内建造建筑
- 核心安全区的格子不会因为局部战斗失败而易主，只有城镇本身被攻陷后安全区才失效
- 安全区为玩家的生产线提供了基本的安全保障，防止早期骚扰导致生产崩溃

### 5.3 缓冲区与资源点争夺

两个玩家的核心安全区之间自然形成缓冲区，这里是主战场。缓冲区内的资源点属于无主状态，双方均可争夺。

资源点的占领规则：
- 派兵进驻资源点格子，持续驻守满1个完整回合（即本回合进驻，下回合结算时完成占领）
- 占领完成后，玩家可以在该格子上建造对应的采取设施
- 兵力撤走后，资源点变回中立状态，对方可以重新争夺
- 已建造的建筑会保留，归新占领方使用——这意味着抢占对方已开发的资源点比开发空地更有价值，鼓励双方持续争夺

### 5.4 城镇间资源传输

资源不会在城镇间自动共享。矿石、木材、粮食等生产资源必须通过道路进行物理传输，从资源点经由道路流向城镇，再从城镇经由道路流向需要这些资源的建筑或兵营。

这个设计让道路系统成为核心战略要素：切断对方的资源传输道路，可以在不占领建筑的情况下让对方的生产线停摆。

## 6. 道路系统

### 6.1 道路的基本概念

道路不是地图的天然属性，而是由玩家主动建造的基础设施。游戏开始时地图上没有任何道路，玩家需要在游戏过程中逐步建立自己的道路网络。

道路有两个核心功能：
- **加速兵种移动**：在道路格上移动消耗1点移动力，非道路格消耗2点移动力。对于移动力只有1的攻城兵和弓手来说，有无道路决定了他们能否在一个回合内抵达目标位置。
- **传输生产资源**：矿石、木材、粮食等实体资源必须通过道路从产出节点流向消费节点。没有道路连接的建筑无法接收资源，也就无法正常运作。

### 6.2 道路建造方式

采用折中方案：玩家指定起点节点和终点节点，系统使用A*算法自动计算最短路径进行建造。如果玩家希望对路径进行细粒度控制（例如绕开某个危险区域），可以结合注意力系统（消耗亲政令牌）手动指定路径点。

道路建造消耗建造点数（全局点数），具体消耗量按路径长度计算（每格消耗1点建造点数）。道路建造在内政阶段发出指令，内政结算时执行。

### 6.3 道路的破坏与修复

道路可以被敌方的破坏兵专门破坏。破坏兵对道路的破坏效果是：该格道路被摧毁，资源传输中断，兵种通过该格时不再享有道路加成。

修复道路需要消耗建造点数（每格1点），并在内政阶段发出修复指令，内政结算时执行。

道路破坏是一种重要的战术手段：精准破坏对方连接矿山到兵工厂的关键道路，可以让对方的武器产线断裂，间接影响其兵种生产能力，而不需要正面强攻。

### 6.4 道路的战略意义

道路网络的拓扑结构本身就是战略博弈的一部分。设计合理的道路网络需要考虑：

- **效率**：资源从产出点到消费点的路径要尽可能短，减少传输损耗
- **冗余**：关键资源传输路径最好有备用路线，防止单点被破坏后整条线路瘫痪
- **安全**：核心道路节点尽量在安全区内，减少被敌方破坏兵袭击的风险
- **扩张**：向资源点延伸的道路同时也是进军路线，道路建设和军事扩张可以结合规划

## 7. 资源系统

### 7.1 资源类型概览

游戏中存在两大类资源：

**生产资源（实体资源）**

需要通过道路进行物理传输，有产地限制，存储在各个城镇的仓库中，城镇间不自动共享。

包含三种：矿石、木材、粮食。

**全局点数（虚拟资源）**

无需传输，全局即时共享，所有城镇共用同一个点数池。玩家每回合固定获得一定数量的全局点数，消耗于建筑建造。

目前设计的全局点数只有一种：建造点数。

### 7.2 三种生产资源详解

**矿石**

来源：矿山（只能建造在山地资源点）
用途：精炼后用于生产高级兵种（骑兵、攻城兵），建造军事建筑（城墙）
战略价值：矿石是军事力量的核心原材料，控制矿石点等于控制对方的兵种上限

**木材**

来源：伐木场（建造在森林资源点附近）
用途：精炼后用于生产工程类兵种（破坏兵），建造普通建筑和道路
战略价值：木材是基础建设的必要材料，早期扩张阶段需求量很大

**粮食**

来源：农场（建造在平原粮食资源点）
用途：维持军队每回合的粮食消耗，生产需要粮食消耗的兵种
战略价值：粮食是军队持续运作的命脉，切断粮食供应会导致军队逐回合减员

### 7.3 资源流动机制

资源的流动遵循以下规则：

1. 资源点上的采取设施每回合产出固定数量的资源
2. 产出的资源沿道路向最近的己方城镇流动（生产结算阶段处理）
3. 流入城镇后进入该城镇的资源仓库
4. 城镇内的建筑和兵营消耗仓库中的资源
5. 如果需要将某城镇的资源传输到另一城镇，必须有道路连接，且按距离有传输消耗（每经过一格消耗一定比例）

如果道路被破坏，资源无法通过该段，流动中断。城镇的仓库中已有的资源不会因为道路破坏而消失，但新的产出无法补充进来。

### 7.4 建造点数

建造点数是全局虚拟资源，每回合固定产出10点（后期可通过特定建筑增加）。

建造点数的消耗场景：
- 建造任何建筑（一次性消耗，详见建筑系统）
- 建造和修复道路（每格1点）
- 亲政令牌的某些操作可能额外消耗建造点数

建造点数不能存储超过一定上限（暂定30点），超出部分在回合结束时清零，鼓励玩家积极建设而不是囤积。

## 8. 生产系统

### 8.1 生产系统的概念

生产系统是将原始资源转化为高级材料的炼化过程。并非所有兵种都可以直接用原始资源生产，高级兵种需要经过一道炼化工序，将原始矿石转化为精炼矿石，将原始木材转化为工程材料。

生产系统体现了产业链的深度：你不能无限造骑兵，因为骑兵需要精炼矿石，而精炼矿石需要冶炼厂持续运转，冶炼厂需要稳定的矿石供应，矿石需要矿山和道路。任何一环断裂，骑兵生产线就会中断。

### 8.2 生产建筑与转化关系

**冶炼厂**

建造消耗：建造点数×3 + 矿石×2
每回合生产消耗：矿石×2
每回合产出：精炼矿石×1
用途：精炼矿石是生产骑兵和攻城兵的必要材料，也用于建造高级军事建筑

**木工坊**

建造消耗：建造点数×3 + 木材×2
每回合生产消耗：木材×2
每回合产出：工程材料×1
用途：工程材料是生产破坏兵和工程营的必要材料

### 8.3 生产链路示意

```
矿山 → [矿石] → 道路传输 → 冶炼厂 → [精炼矿石] → 骑兵场/攻城营
伐木场 → [木材] → 道路传输 → 木工坊 → [工程材料] → 工程营
农场 → [粮食] → 道路传输 → 城镇仓库 → 兵种维持消耗
```

高级兵种的生产需要同时满足精炼材料和粮食的双重需求，这意味着玩家需要同时维护多条生产链路，而不是专注于单一资源。

### 8.4 生产效率与瓶颈

每个生产建筑每回合只能进行固定次数的转化，不能无限叠加。这制造了产量瓶颈：即使你有充足的矿石，一座冶炼厂每回合只能生产一份精炼矿石。想要提高产量，需要建造更多的冶炼厂，但这需要更多的建造点数和矿石，也占据更多的格子。

这个瓶颈设计让玩家必须做资源规划，提前考虑需要多少高级兵种，再反推需要多少生产建筑，再反推需要多少原始资源点。

## 9. 建筑系统

### 9.1 建筑消耗的两种形式

所有建筑的消耗分为两类，概念上必须区分清楚：

**建造消耗**：建筑建成时的一次性消耗。包括建造点数和部分材料。建筑建成后，这部分消耗不可退回。

**生产消耗**：建筑每回合正常运作的持续消耗。即产线运转的原料投入，转化为产出物。如果某回合资源不足以支付生产消耗，该建筑本回合停止运作，不产出任何东西。

### 9.2 生产建筑详表

**资源采取类**

| 建筑名 | 建造消耗 | 生产消耗（每回合） | 产出（每回合） | 建造位置限制 |
|---|---|---|---|---|
| 伐木场 | 建造点数×2 | 无 | 木材×2 | 森林资源点附近（相邻格） |
| 矿山 | 建造点数×3 | 无 | 矿石×2 | 山地资源点上 |
| 农场 | 建造点数×2 | 无 | 粮食×2 | 平原粮食资源点上 |

资源采取类建筑建造后自动运作，无需持续投入原料，产出会沿道路流向最近城镇。

**食物生产类**

| 建筑名 | 建造消耗 | 生产消耗（每回合） | 产出/效果 | 说明 |
|---|---|---|---|---|
| 粮仓 | 建造点数×2 + 木材×2 | 无 | 粮食存储上限+20 | 建在城镇内，提高仓库容量 |

**生产系统类（炼化）**

| 建筑名 | 建造消耗 | 生产消耗（每回合） | 产出（每回合） | 说明 |
|---|---|---|---|---|
| 冶炼厂 | 建造点数×3 + 矿石×2 | 矿石×2 | 精炼矿石×1 | 高级兵种必须 |
| 木工坊 | 建造点数×3 + 木材×2 | 木材×2 | 工程材料×1 | 工程类兵种必须 |

**兵种生产类**

| 建筑名 | 建造消耗 | 生产消耗（每回合） | 产出 | 说明 |
|---|---|---|---|---|
| 兵营 | 建造点数×3 + 矿石×1 | 矿石×1 + 粮食×1 | 步兵×1 或 弓手×1 | 每回合选择生产一种 |
| 骑兵场 | 建造点数×4 + 精炼矿石×1 | 精炼矿石×1 + 粮食×2 | 骑兵×1 | 需要冶炼厂支撑 |
| 工程营 | 建造点数×4 + 工程材料×1 | 工程材料×1 + 粮食×1 | 攻城兵×1 或 破坏兵×1 | 每回合选择生产一种 |

### 9.3 军事建筑详表

军事建筑用于防御和控制，不生产兵种，但提供战斗加成或特殊功能。

| 建筑名 | 建造消耗 | 生产消耗（每回合） | 功能 | 说明 |
|---|---|---|---|---|
| 城墙 | 建造点数×3 + 矿石×2 | 无 | 提升城镇防御值+15 | 可叠加，最多建3层 |
| 箭塔 | 建造点数×2 + 木材×2 | 粮食×1 | 对范围内敌军造成8点伤害/回合 | 攻击范围2格，断粮则停止攻击 |
| 烽火台 | 建造点数×1 | 无 | 扩展视野范围+3格 | 可以提前发现敌方动向 |

### 9.4 建筑的位置限制

- 所有建筑只能建造在己方控制的格子上（核心安全区内，或通过兵力占领的格子）
- 资源采取类建筑有地形限制（见上表）
- 同一格子只能有一座建筑
- 军事建筑可以建造在城镇的任意安全区格子内

## 10. 兵种系统

### 10.1 兵种概览

游戏共有5种兵种，分别针对不同的战术场景。每种兵种有明确的专攻方向和弱点，形成相互克制的关系。

| 兵种 | 特攻方向 | 建造消耗 | 移动力/回合 | 攻击力 | 生命值 |
|---|---|---|---|---|---|
| 步兵 | 主战场均衡 | 矿石×1 + 粮食×1 | 2格（道路）/1格（非道路） | 10 | 30 |
| 弓手 | 远程压制 | 木材×1 + 粮食×1 | 1格（道路）/无法穿越非道路山地 | 8（远程） | 20 |
| 骑兵 | 快速机动 | 精炼矿石×1 + 粮食×2 | 3格（道路）/2格（非道路） | 12 | 25 |
| 攻城兵 | 城堡/城墙 | 精炼矿石×2 + 粮食×1 | 1格（任何地形） | 5（野战）/30（攻城） | 35 |
| 破坏兵 | 道路/建筑 | 矿石×1 + 木材×1 | 2格（道路）/1格（非道路） | 5（战斗）/20（破坏） | 20 |

### 10.2 各兵种详细说明

**步兵**

步兵是最基础的兵种，没有特别突出的长处，也没有明显的弱点。适合作为主力部队用于正面战场，也可以作为其他特殊兵种的护卫。步兵对破坏兵有克制优势，能有效阻止对方的道路破坏行动。

**弓手**

弓手具有2格的攻击射程，可以在不进入敌方格子的情况下发起攻击。弓手对骑兵有克制优势，能有效拦截快速突进的骑兵。弓手自身很脆弱，在近战中极为不利，需要步兵保护。弓手在森林地形中受到隐蔽加成影响较小（自身攻击不受影响，但己方防御加成依然有效）。

**骑兵**

骑兵是移动速度最快的兵种，在有道路的情况下每回合可移动3格，非常适合快速奔袭、切断后方道路、或者包抄敌方侧翼。骑兵在首回合冲锋时具有1.5倍攻击加成（突击加成），代表高速冲击的杀伤力。但骑兵无法进入山地格子，且维持成本高（需要精炼矿石和大量粮食）。

**攻城兵**

攻城兵是专门设计用于攻破城镇防御的兵种。在野战中攻城兵表现很差（攻击力只有5），但对城墙和城堡发动攻击时，伤害倍率为×3（即实际攻击力30）。攻城兵移动速度极慢，需要步兵保护才能安全抵达目标城镇。一旦攻城兵到达主城格子，每回合可以对主城造成大量伤害。

**破坏兵**

破坏兵不以战斗为主要目的，而是专门用于破坏对方的基础设施。破坏兵可以在一个回合内摧毁一段道路，或对建筑造成大量伤害（×3倍效果）。破坏兵在正面战斗中很弱，必须避开对方的步兵巡逻队。破坏兵是切断对方生产线的核心工具，也是本游戏最具特色的战术兵种之一。

### 10.3 兵种克制关系

```
骑兵 → 步兵：骑兵对步兵攻击倍率×1.5（冲击优势）
步兵 → 破坏兵：步兵对破坏兵攻击倍率×1.5（近战压制）
弓手 → 骑兵：弓手对骑兵攻击倍率×1.5（远程拦截）
攻城兵 → 城墙/城堡：攻击倍率×3（专业攻城）
破坏兵 → 道路/建筑：破坏效率×3（专业破坏）
```

### 10.4 军队粮食消耗

每回合所有在战场上的兵种都会消耗粮食维持。如果城镇仓库中的粮食不足以支付本回合的军队消耗，军队开始因断粮产生减员（每回合生命值-5%，直到粮食恢复供应）。

这个机制让粮食生产线成为军事行动的命脉。长期大规模作战必须有稳定的粮食保障，否则即使在战场上占据优势，也会因为后勤断裂而失败。

## 11. 战斗系统

### 11.1 基础伤害公式

```
实际伤害 = 基础攻击力 × 兵种克制系数 × 地形系数 × 数量

地形系数：
  进攻方在山地攻击守方：×0.8（地势不利）
  守方在森林被攻击：×0.7（隐蔽加成，即减少30%受到的伤害）
  其他情况：×1.0
```

### 11.2 攻城计算

攻城是一套独立的计算逻辑，与野战不同：

```
主城当前防御值 = 基础防御100 + 城墙加成（每层+15）+ 守城步兵加成（每个步兵+3）

攻城伤害（每回合）= 攻城兵数量 × 30 × (1 - 城墙防御系数)
城墙防御系数 = min(城墙层数 × 0.1, 0.5)  // 最高减伤50%

守城反击（每回合）= 守城步兵数量 × 5 + 箭塔数量 × 8
```

主城的"血量"独立于控制值概念，是一个从满值开始递减的数值。当主城血量归零时，该玩家判负，不需要等到下一回合。

### 11.3 战区系统

战区是玩家手动划定的战略区域，用于组织战斗阶段的指挥层级。

**战区划定规则：**
- 玩家可以在游戏中随时重新划定战区，划定操作在战斗阶段开始前完成
- 战区是己方控制节点的集合，同一个节点只能属于一个战区
- 建议划定2～3个战区，过多战区会增加管理负担，过少则失去分线指挥的意义
- 战区名称由玩家自定义（如"北线"、"中路"、"南线"）

**战区指令：**
玩家给每个战区下达一条战略意图指令，指令类型包括：
- **全力进攻 [目标节点]**：集中战区内兵力向指定目标推进
- **稳守待机**：维持当前阵线，不主动出击，优先防御
- **骚扰破坏**：派遣破坏兵袭击对方道路和建筑，避免正面交战
- **包抄 [目标节点]**：绕过正面防线，从侧翼迂回进攻
- **撤退 [方向]**：有序后撤，减少损失

战区指令是免费行动，不消耗令牌。

### 11.4 军事部长指令拆解

玩家发布战区指令后，军事部长根据指令内容、战区内的兵力组成、以及其自身的性格倾向，将战区指令拆解为具体的部队行动指令，以流式文本方式呈现给玩家：

```
"陛下，北线'全力进攻虎牢关'的命令臣已传达。
 臣的安排如下：
 - 北线步兵第一队（5人）从铁岭出发，沿官道向虎牢关正面推进
 - 北线骑兵队（3人）绕道森林北侧，尝试包抄虎牢关侧翼
 - 北线弓手队（4人）在铁岭原地待命，为步兵提供远程支援
 
 臣注意到敌方虎牢关似乎有约8名守军，
 正面强攻有一定风险，骑兵包抄若能成功则可解决这一问题。
 （置信度：中，敌方守军数量来自上回合情报，可能有变）"
```

### 11.5 微操窗口

军事部长流式展示完具体指令后，进入微操窗口，玩家有限时（具体时长待测试确定）进行审阅和干预：

- **遵循（默认）**：不做任何操作，所有指令按部长安排执行
- **消耗令牌否决某条指令**：消耗1个亲政令牌，撤销某支部队的行动，该部队本回合原地待命
- **消耗令牌修改为精确微操**：消耗1个亲政令牌，手动指定某支部队的具体目标格子和行动，完全覆盖部长的安排

微操窗口结束后，双方提交，进入战斗结算。

### 11.6 战斗结算流程

战斗结算分为以下步骤，严格按顺序执行：

**Step 0：路径计算**

对所有本回合有移动指令的部队，使用A*算法计算其实际移动路径。路径计算需考虑：道路加速（道路格移动消耗1，非道路格消耗2）、山地对骑兵的阻挡、敌方控制节点的阻挡（不能直接穿越，必须交战）。

路径计算完成后，每支部队得到一条完整的路径序列（含本回合实际移动步数的截止点）。

**Step 1：冲突检测**

扫描所有部队的移动路径，检测以下三类冲突：

*边冲突（换家/对向移动）*：检查是否有不同阵营的部队在同一条边上做方向相反的移动。这是换家的核心检测逻辑。两支部队对向经过同一条边，在该边中间（取路径中间的格子作为交战点）强制发生战斗。

*节点冲突（终点相同）*：检查是否有不同阵营的部队在本回合结束时位于同一格子。若有，在该格子发生战斗。

*追及冲突（同向追上）*：检查是否有移动速度不同的部队，在移动过程中同一时间步经过同一格子。按时间步展开路径进行逐步检测。

**Step 2：冲突排序**

所有检测到的冲突按发生时间步升序排列（越早发生的越先结算）。同一时间步的冲突，按参与部队中最高速度降序排列（速度快的优先）。

**Step 3：依次结算冲突**

按排序依次结算每个冲突。每次结算后立即更新游戏状态（兵力损耗、位置变化），然后重新检查后续冲突是否仍然有效（被消灭的部队参与的冲突自动失效）。

战斗结算公式：
```
双方同时造成伤害：
  A对B的伤害 = A的攻击力 × 克制系数 × 地形系数 × A的数量
  B对A的伤害 = B的攻击力 × 克制系数 × 地形系数 × B的数量
  
伤亡换算：
  伤亡数量 = floor(受到的总伤害 / 每个单位的生命值)
  
胜负判定：
  全歼对方：该格子归进攻方
  双方都有剩余：守方守住，进攻方被击退到上一格
```

**Step 4：攻城结算**

最后处理攻城兵对城墙和主城的伤害，按攻城计算公式执行（见11.2节）。

**Step 5：胜负检测**

攻城结算后检查所有城镇的血量，若有主城血量归零，游戏立即结束，该城镇所属玩家判负。

### 11.7 换家的特殊处理

完全换家情形（双方部队完全互换位置）会被检测为边冲突，强制在路径中点发生战斗，不允许完全错开。

若双方主城同一回合血量同时归零（极端情况），判为平局。地图设计上保证双方主城距离足够远，这种情况几乎不会出现。

## 12. AI 部长系统

### 12.1 系统概述

AI部长系统是本游戏最核心的创新设计，也是"深度使用AI"主题的主要体现。部长不是简单的建议提示框，而是：

- 玩家感知游戏世界的唯一接口（玩家看到的所有信息都经过部长的过滤和处理）
- 在政策框架内自主执行决策的代理人（部长的行动会直接改变游戏状态）
- 跨越整局游戏的叙事载体（部长有记忆、有感情、有立场）

技术实现上，每次需要生成部长行为时，服务端将当前游戏状态序列化为结构化prompt，调用LLM API，解析返回的结构化JSON，执行其中的actions字段，并将report字段以流式方式推送给客户端显示。

### 12.2 部长角色池系统

部长的性格不由职位固定，而是由玩家从角色池中选择。类似于欧陆风云4的顾问系统，玩家在游戏开始时从可用的部长候选人中为每个职位选择一名部长。

**部长属性**

每位部长候选人有以下属性，部分对玩家可见，部分不可见：

| 属性 | 玩家可见性 | 说明 |
|---|---|---|
| 姓名 | 完全可见 | 部长的名称，用于叙事 |
| 职位适配 | 完全可见 | 该部长适合担任哪个职位 |
| 能力值（1-10） | 完全可见 | 自主行动的成功率和质量 |
| 性格倾向 | 模糊可见（描述词） | 如"果敢"、"谨慎"、"贪婪"，影响行为偏好 |
| 忠诚度（1-10） | 不可见 | 是否如实汇报，是否私自行动 |
| 野心值（1-10） | 不可见 | 是否越权争夺其他部门资源 |

**属性对行为的影响**

能力值高的部长：自主行动成功率高，汇报信息更准确，给出的建议更有参考价值。

性格倾向"果敢"的部长：倾向于主动建议进攻性行动，低估风险，可能在局势紧张时给出过于激进的建议。

忠诚度低的部长：汇报时会有意无意地隐瞒对自己不利的信息，可能夸大某些危险以争取更多资源。

野心值高的部长：会主动争夺其他部门的资源预算，在给玩家的建议中可能有私心。

### 12.3 三种部长职位

**军事部长（Gamejam必做）**

职责范围：前线兵力状态汇报、战区指令拆解为具体部队行动、自主调兵决策（在政策框架内）。

典型汇报内容：前线节点的兵力分布、敌方动向（基于烽火台侦察）、战损情况、建议增援或进攻的节点。

自主行动权限：在"备战"或"扩张"国策下，可以主动将后方闲置兵力调往前线；在前线节点危急时，可以在不请示的情况下从临近节点抽调兵力增援。

**农业部长（Gamejam必做）**

职责范围：资源生产状态汇报、道路传输效率分析、建筑建造建议、自主修缮道路和规划建造（在政策框架内）。

典型汇报内容：各资源点的产出状况、粮食储备是否充足、哪条道路传输效率异常、建议新建哪类生产建筑。

自主行动权限：在"休养"国策下，可以主动消耗建造点数修缮受损道路；在发现新资源点被占领后，可以自主规划并开始建造采取设施（消耗建造点数）。

**外交部长（Gamejam加分项）**

职责范围：敌方情报分析、注意力焦点推断、扰乱敌方情报（虚假信息）。

典型汇报内容：根据可观测到的敌方兵力变化推断其战略意图（附置信度）、推测敌方君主本回合可能关注的区域、分析道路破坏事件背后的战略含义。

自主行动权限：在玩家授权下，可以向敌方发出虚假的外交信号，干扰对方外交部长的情报分析。

### 12.4 部长行为触发表

**军事部长触发条件与行为**

| 前置条件 | 部长行为 | 对游戏的实际影响 |
|---|---|---|
| 国策=备战 | 主动将闲置兵力调往前线 | 后方某节点兵力-N，前线+N |
| 国策=备战 + 粮食储量<30% | 无视粮食危机继续调兵 | 军队开始出现断粮减员风险 |
| 前线节点兵力<敌方兵力×0.6 | 上报告急，建议增援，等待指示 | 汇报发出，无自主行动 |
| 前线节点告急 + 玩家无响应2回合 | 自主从后方抽调兵力增援 | 后方某节点控制力-20，前线+15 |
| 连续2回合建议被拒绝 | 建议趋于保守，不再主动建议进攻 | 自主行动减少，等待指示 |
| 敌方出现骑兵 + 己方弓手不足 | 夸大骑兵威胁 | 汇报中敌方骑兵数量×1.2（不实） |
| 国策=扩张 + 附近有空城堡 | 建议派兵占领，可能自主派遣小股部队试探 | 消耗粮食×2，派出小股部队 |
| 己方连胜2回合 | 建议扩大战果，一鼓作气 | 若玩家采纳，兵力集中进攻，后方空虚 |
| 国策=休养 | 建议不主动出击，保存兵力 | 自主调兵频率降低 |

**农业部长触发条件与行为**

| 前置条件 | 部长行为 | 对游戏的实际影响 |
|---|---|---|
| 国策=休养 | 主动修复受损道路 | 消耗建造点数，修复某段道路 |
| 粮食流量<70% | 汇报粮食供应略有不足 | 轻描淡写，玩家可能忽视 |
| 粮食流量<40% | 如实上报，建议暂停高消耗兵种生产 | 紧急汇报，建议减少骑兵骑场运作 |
| 粮食流量<20% | 紧急警报，建议立即处理 | 此时军队已开始断粮减员 |
| 军事部长行动消耗了农业预算 | 向玩家抱怨 | 汇报中表达不满，降低军事部长在玩家心中的可信度 |
| 国策=扩张 | 消极配合，节省资源 | 建造速度-20%，优先维持现有产线 |
| 新占领资源点 | 主动规划开发 | 若玩家未明确阻止，自动发出建造指令 |
| 道路被破坏 | 上报损失，建议修复 | 汇报受损道路位置，等待玩家指示 |
| 玩家连续3回合采纳建议 | 越权使用军事预算 | 悄悄将部分矿石用于修建额外粮仓 |

**外交部长触发条件与行为**

| 前置条件 | 部长行为 | 对游戏的实际影响 |
|---|---|---|
| 敌方注意力焦点可推断 | 生成情报汇报 | 汇报敌方注意力可能位置（70%准确率） |
| 敌方连续2回合扩张资源点 | 生成战略意图分析 | 推测敌方正在备战（60%准确率） |
| 己方明显处于劣势 | 建议虚张声势 | 若玩家采纳，干扰敌方情报准确性 |
| 敌方破坏了己方道路 | 分析敌方战略意图 | 推测是试探还是全面进攻的前兆 |
| 连续2回合无有效情报 | 生成低置信度情报 | 内容可能部分或完全错误 |
| 己方连续失败 | 建议暂时示弱，拖延时间 | 外交层面的缓兵之计，本身无实际效果 |

### 12.5 部长记忆系统

部长跨回合保持记忆，这些记忆会影响后续的汇报内容和行为。

记忆内容包括：
- 历史上提出的建议以及玩家的采纳/拒绝决定
- 历史上自主行动的结果（成功/失败）
- 与其他部长之间发生过的冲突事件
- 游戏中发生的重大事件（主城受到攻击、关键资源点丢失等）

记忆的影响方式：
- 建议被反复拒绝 → 部长语气变得保守，不再主动建议
- 建议被采纳且结果良好 → 部长语气变得自信，可能开始越权
- 自主行动结果很差 → 部长开始更多请示，减少自主决策
- 与其他部长的争执 → 后续汇报可能带有对其他部长的评价

## 13. 政策系统

### 13.1 政策系统概述

政策系统是玩家发布宏观意志的渠道。玩家不直接操控游戏世界的每一个细节，而是通过发布政策方向，让AI部长在这个框架内自主执行。

这个设计让玩家的角色更接近真实的领导者：你决定大方向，具体执行交给部下，但部下不一定按你的期望执行，而且执行结果需要时间才能看到。

### 13.2 宏观国策

宏观国策代表当前整个王国的施政重心，每次更换需要消耗一定代价（暂定间隔至少3回合才能再次更换，防止频繁切换）。

**备战（Ready for War）**

效果：所有部长的决策权重向军事方向倾斜。军事部长更积极地自主调兵，农业部长优先保证军粮供应而非基础建设，外交部长重点收集敌方军事情报。

令牌加成：战斗阶段令牌效果×1.5（亲自微操的精准度提高）。

副作用：基础建设速度降低，资源点开发优先级下降，长期备战会消耗大量粮食储备。

**扩张（Expansion）**

效果：部长们积极向外拓展，军事部长主动寻找可占领的空城堡和资源点，农业部长加快开发新占领区域的资源建筑。

令牌加成：本回合建造成本降低10%（扩张国策下建设效率提高）。

副作用：防御重视度下降，边境节点可能因为兵力分散而变得脆弱。

**休养（Recuperation）**

效果：部长们以恢复和巩固为主，农业部长积极修缮道路、补充粮食储备，军事部长减少主动出击，专注于修缮防御工事。

令牌加成：每回合额外获得1个亲政令牌（+1令牌）（君主有更多精力处理内政细节）。

副作用：军事行动效率降低，主动进攻时部长积极性不高。

**外交（Diplomacy）**

效果：外交部长的情报活动更加活跃，情报准确率提升，还可以对对方发出外交信号（影响对方的信息判断）。军事部长保持守势，不主动挑起战斗。

令牌加成：外交部长提供的情报置信度提升（更可靠）。

副作用：军事准备不足，被动应对突然袭击时响应较慢。

### 13.3 专项指示

专项指示是每回合可以对单个部长发出的方向性调整，不替代宏观国策，而是在国策框架内进行微调。每回合最多发出一条专项指示（免费行动）。

示例：
- 对军事部长："本回合优先保护铁岭，不要主动出击"
- 对农业部长："优先修复北线道路，推迟其他建设项目"
- 对外交部长："集中精力分析对方东线的动向"

专项指示不是命令，而是方向。部长会根据自己的性格和能力理解并执行，结果可能和玩家预期有所偏差。

## 14. 注意力系统（亲政令牌）

### 14.1 系统概述

亲政令牌代表君主亲自干预游戏世界的能力配额。每回合令牌数量有限，用完就没有，不可叠加到下回合。这个稀缺性制造了每回合的核心决策压力：

> 这回合最需要我亲自关注的是哪件事？

大多数时候，部长们的自主执行已经足够，玩家不需要每件事都亲力亲为。但当局势关键、部长判断可疑、或者需要精确干预时，令牌就是最宝贵的资源。

### 14.2 令牌基础规则

- 每回合开始时获得3个亲政令牌
- 令牌不可叠加（本回合未使用的令牌在回合结束时清零）
- 令牌分配在内政阶段和战斗阶段均可使用

### 14.3 令牌使用场景

**内政阶段（令牌用途）**

*亲自建造/拆除建筑（消耗1个令牌）*：绕过部长的建造决策，直接指定格子和建筑类型进行建造。这样的建造立即进入建造结算队列，不经过农业部长的过滤。适用于：部长规划方向与玩家不符、紧急需要某种建筑、不信任部长的当前判断。

*查看某区域真实状态（消耗1个令牌）*：消除该区域的信息迷雾，在当前回合看到该区域的真实数据（而不是部长汇报的经过过滤的数据）。真实数据包括：准确的节点控制值、实际的资源流量、真实的敌方兵力分布（若在视野范围内）。适用于：怀疑部长汇报不准确、需要验证某个关键节点的实际情况。

*手动调整生产线资源流向（消耗1个令牌）*：直接指定某个资源从产地流向特定城镇，覆盖系统的自动路径规划。适用于：资源分配不符合当前战略需求、紧急需要将资源优先输送到某处。

*否决部长上回合自主行动（消耗1个令牌）*：撤销部长在上一回合做出的某次自主行动，并要求其恢复原状（如果可能）。注意：如果部长的行动已经产生了不可逆的后果（如消耗的资源无法归还），否决只能阻止进一步的后续行动，不能完全逆转。

**战斗阶段（令牌用途）**

*否决部长某条具体部队指令（消耗1个令牌）*：撤销军事部长为某支部队安排的行动，该部队本回合原地待命，不执行任何移动或攻击。

*修改为精确微操（消耗1个令牌）*：完全覆盖军事部长对某支部队的安排，由玩家手动指定该部队的精确目标格子和行动类型。

### 14.4 令牌数量的修正因素

基础令牌数量（3个/回合）会受到以下因素的调整：

| 条件 | 令牌变化 |
|---|---|
| 国策=休养 | +1（君主有更多精力处理内政） |
| 某部长信任度高（连续采纳且结果良好） | 该部长负责区域令牌消耗-1（可靠的部长不需要亲自监督） |
| 某部长信任度低（多次拒绝或结果差） | 该部长负责区域令牌消耗+1（需要更多监督） |

### 14.5 注意力与信息迷雾的关系

亲政令牌的"查看真实状态"功能是打破信息迷雾的主要手段。平时玩家看到的信息都是经过部长过滤的主观数据，消耗令牌后可以看到某个区域的客观真实数据。

这个设计制造了一个有趣的元决策：是否值得花费一个令牌来验证某个部长的汇报是否准确？如果部长一向可靠，验证是浪费令牌；如果部长最近行为可疑，验证可能揭示重要真相。

## 15. 信息不对称系统

### 15.1 系统概述

信息不对称是本游戏叙事体验的核心支柱。玩家不是上帝，不能看到客观的游戏状态，而是通过AI部长构建的主观图景来理解世界。

### 15.2 双轨信息呈现

所有游戏信息以双轨方式呈现给玩家：

**叙事轨（LLM生成）**：部长用自然语言描述的、带有主观色彩的世界图景。例如："虎牢关局势有些严峻，守将来报说敌军正在集结。"

**数值轨（规则计算）**：客观数据的标注，但可能有延迟或置信度标注。例如：[虎牢关 控制值：42 ↓ 数据来源：上回合 置信度：高]

两轨同时显示，玩家既能感受叙事氛围，也能看到支撑决策的数字依据。重要的是：叙事轨和数值轨可能不完全一致——部长可能言辞夸张但数字显示问题不大，或者言辞轻描淡写但数字已经亮红灯。

LLM挂了或响应超时时，游戏退化为只显示数值轨，叙事轨消失，但游戏本身依然可以正常运行。这保证了游戏的稳定性不依赖LLM的100%可靠。

### 15.3 三种信息失真方式

**延迟**

前线节点的数据有一回合的延迟。玩家在当前回合看到的前线状态，实际上是上回合末的快照。这意味着可能已经恶化的局势要到下一回合才能在数字上体现，但部长可能（也可能不）提前感知到迹象并在汇报中有所提示。

延迟只发生在前线和边界区域，玩家自己核心安全区内的信息是实时准确的。

**过滤**

每个部长只汇报自己职责范围内的信息，不会主动越界。农业部长不会告诉你前线的兵力分布，即使他知道。军事部长不会主动分析粮食供应问题，除非他认为这直接影响到军事行动。

玩家必须主动向特定部长问询，消耗一个回合的行动机会，才能获得超出部长常规汇报范围的信息。

**失真**

部长的汇报带有主观色彩，反映的是他的认知和立场，不是纯粹的客观事实。

忠诚度低的部长可能轻描淡写某些问题（不想显得自己管理失职）或夸大某些危险（想争取更多资源投入）。

外交部长的情报分析可能受限于情报来源的质量，置信度是真实反映的，但"60%置信度"本身意味着有40%的概率他的判断是错的。

### 15.4 安全阀设计

为了防止信息失真让玩家完全无所适从，设计了以下安全阀：

**核心区信息准确**：玩家自己核心安全区内的信息永远是准确的、实时的。你能精确看到自己主城的血量、核心区内建筑的状态、己方资源仓库的数量。失真和延迟只发生在边界和对方领土。

**数值轨兜底**：即使叙事轨的内容令人迷惑，数值轨的数字提供了最基础的决策依据。玩家永远可以依靠数字，叙事轨是额外的信息层。

**失真程度随阶段变化**：游戏开局时信息相对准确，部长建议可靠度高。随着局势发展到中期，前线信息开始有更多延迟和失真。到达危机时刻，信息失真最为严重，部长之间开始出现更多矛盾的建议。这个曲线保证玩家有足够的时间适应游戏的信息机制，而不是一开始就被淹没。

## 16. 回合结构

### 16.1 总体框架

每个游戏回合分为两个大阶段：内政阶段和战斗阶段，严格串行执行（内政阶段双方都提交后，才进入战斗阶段）。两个阶段都有时间限制，超时后部长全权接管。

### 16.2 回合开始

每个新回合开始时，服务端触发以下操作：

首先推送上一回合的结算结果给双方客户端，包括：建造结算报告、生产结算报告、战斗结算动画数据、主城血量变化。

然后异步调用LLM，为每个玩家的每位部长生成本回合汇报。汇报生成完成后，以流式方式推送给对应玩家。部长汇报的生成是异步的，不阻塞玩家进入内政阶段，玩家可以在汇报流式显示的过程中开始进行其他操作。

### 16.3 内政阶段

双方玩家同时进行内政阶段，互相看不到对方的操作。时间限制60秒（待测试后调整）。

**免费行动（不消耗令牌，不限次数）**

- 审阅部长汇报：查看各部长的文字汇报和数值数据
- 发布/修改宏观国策：切换当前国策（受3回合冷却限制）
- 发布专项指示：向某个部长发出本回合的方向性调整（每回合最多1条）

**令牌行动（消耗亲政令牌，每回合基础3个）**

- 亲自建造/拆除建筑（1个令牌）
- 查看某区域真实状态（1个令牌）
- 手动调整生产线资源流向（1个令牌）
- 否决部长上回合自主行动（1个令牌）

**超时处理**

若玩家在60秒内未手动提交，系统自动提交，进入内政结算。未完成的令牌操作视为放弃，部长按当前国策全权处理内政。

### 16.4 内政结算

双方都提交后，服务端进行内政结算，双方实时看到结算过程（可以是简单的文字日志或动画）。

结算顺序：

**建造结算**：首先执行玩家通过令牌亲自指定的建造，然后执行部长根据政策自主发出的建造指令。所有建造消耗从建造点数和对应资源中扣除。

**生产结算**：依次处理资源流动（从资源点沿道路流向城镇仓库）、生产系统转化（冶炼厂、木工坊的原料→成品转化）、兵种生产（兵营、骑兵场、工程营的生产消耗和产出）、军队粮食消耗（所有在战场上的部队消耗粮食，不足则减员）。

### 16.5 战斗阶段

内政结算完成后，进入战斗阶段。双方玩家同时进行，互相看不到对方的操作。时间限制60秒（待测试后调整）。

**战区指令（免费行动）**

玩家为每个战区下达一条战略意图指令：全力进攻、稳守待机、骚扰破坏、包抄、撤退。战区的划分由玩家在游戏进行中随时调整。

**部长指令拆解**

玩家提交战区指令后（或达到一定时间节点时），军事部长开始将战区指令拆解为具体部队行动，以流式文字方式显示给玩家，让玩家了解部长的具体安排。

**微操窗口（令牌行动）**

在部长展示完具体指令后，玩家有限时进行审阅。可以消耗令牌否决某条具体指令（1个令牌）或将其修改为精确微操（1个令牌）。

**超时处理**

若玩家在时间内未提交，系统自动提交，部长的指令全部按默认执行，玩家的战区指令生效，微操操作放弃。

### 16.6 战斗结算

双方都提交后进入战斗结算，双方实时观看结算动画。结算流程严格按以下顺序执行：

1. 路径计算（A*寻路，考虑道路、地形、敌方阻挡）
2. 冲突检测（边冲突、节点冲突、追及冲突）
3. 冲突排序（按时间步升序，同时间步按速度降序）
4. 依次结算冲突（每次结算后更新状态，重新检测新冲突）
5. 攻城结算（最后执行，攻城兵对城墙和主城造成伤害）
6. 胜负检测（主城血量归零即判负）

### 16.7 回合结束

战斗结算和胜负检测完成后，回合结束，进入下一回合开始阶段。服务端异步开始生成下回合各部长的汇报，准备在下回合开始时推送。

## 17. 胜负条件

### 17.1 主要胜利条件：攻破主城

当己方的攻城兵对对方主城造成足够的持续伤害，使主城血量归零时，该玩家的主城被攻破，判负，对方判胜。

主城血量计算：
```
主城最大血量 = 100 + 城墙加成（每层城墙+15，最多3层=+45）+ 守城步兵加成（每个步兵+3）
```

主城血量不会自动回复，每回合被攻城兵攻击后减少。守城的步兵和箭塔每回合会对攻城方造成反击伤害，可以延缓主城血量的消耗。

### 17.2 平局兜底

Gamejam版本建议加入回合上限作为平局兜底（暂定30回合），防止游戏因双方僵持而无限拖延。若达到回合上限时双方主城都未被攻破，判为平局。

平局结果对Gamejam来说是可以接受的，比游戏卡死更好。

## 19. 技术架构

### 19.1 技术栈

| 层级 | 技术选型 | 选型理由 |
|---|---|---|
| 客户端 | Unity | 团队熟悉，生态成熟，跨平台 |
| 服务端语言 | Go 或 Node.js | Go并发性能好适合游戏服务器；Node.js LLM生态更好，SDK更丰富 |
| 通信协议 | WebSocket | 回合制不需要UDP，WebSocket实现简单且够用 |
| 状态存储 | Redis | KV存储天然适合游戏状态，支持pub/sub，断线重连友好 |
| LLM接入 | Anthropic API | 结构化输出稳定，JSON mode可靠，支持流式输出 |
| 寻路算法 | A* | 标准实现，格子地图上表现良好，有现成库 |

### 19.2 核心数据结构

```typescript
// 游戏状态（服务端权威状态）
interface GameState {
  game_id: string
  turn: number
  phase: 'domestic' | 'combat' | 'settlement'
  players: Player[]
  network: Network
}

// 网络（地图的核心抽象）
interface Network {
  nodes: Node[]
  edges: Edge[]
}

interface Node {
  id: string
  position: [number, number]
  type: 'resource' | 'road' | 'strategic' | 'castle'
  terrain: 'plain' | 'mountain' | 'forest' | 'river'
  owner: string | null       // player_id or null
  building: Building | null
  units: Unit[]
  resource_type?: 'ore' | 'wood' | 'food'  // 资源点类型
}

interface Edge {
  from: string               // node_id
  to: string                 // node_id
  has_road: boolean
  road_health: number        // 0-100，0=被摧毁
  active: boolean            // 是否畅通（两端节点控制情况决定）
}

// 玩家状态
interface Player {
  id: string
  resources: {
    ore: number
    wood: number
    food: number
    refined_ore: number
    engineering_material: number
    build_points: number
  }
  ministers: Minister[]
  current_policy: Policy
  tokens: number             // 本回合剩余令牌数
  war_zones: WarZone[]
  main_castle_hp: number
}

// 部长
interface Minister {
  id: string
  role: 'military' | 'agriculture' | 'diplomacy'
  name: string
  ability: number            // 1-10，影响自主行动质量
  personality: string        // 性格倾向描述词
  loyalty: number            // 1-10，影响汇报真实度（服务端隐藏）
  ambition: number           // 1-10，影响越权行为（服务端隐藏）
  memory: MinisterMemory[]   // 历史记忆
}

interface MinisterMemory {
  turn: number
  type: 'suggestion' | 'self_action' | 'conflict' | 'event'
  content: string
  outcome?: string
  player_response?: 'adopted' | 'rejected' | 'ignored'
}

// 战区
interface WarZone {
  id: string
  name: string
  node_ids: string[]
  directive: 'attack' | 'defend' | 'harass' | 'flank' | 'retreat'
  target_node?: string
}
```

### 19.4 LLM调用架构

LLM调用在服务端异步进行，不阻塞游戏主循环。

调用时机：
- 回合结束时，异步开始生成下回合各部长的汇报
- 内政结算时，触发部长的自主行动决策
- 战斗阶段开始时，军事部长异步生成战区指令拆解

超时处理：LLM调用设置超时（暂定5秒），超时则使用预设的fallback响应（基于规则的简单建议），保证游戏不因LLM响应慢而卡住。

流式输出：部长汇报支持流式输出，服务端收到LLM的stream chunk后立即转发给客户端，减少玩家等待感知时间。
